## 1. 什么是 MergeTool

MergeTool 是一款把**大量文本文件合并成一份报告**的桌面工具。
典型使用场景：

- 把整个项目的源码合并成一份文件，方便投喂给 AI 大模型。
- 归档一批日志、配置、文档，生成单一可检索的文本。
- 在投稿、代码审查、作业提交时，把分散文件打包成一份完整记录。

它最大的特点是：

- **图形化目录树**：像文件资源管理器一样勾选要合并的文件。
- **自动编码识别**：中文乱码问题基本不会发生。
- **输出带元信息**：每个文件都标注绝对路径、编码、大小。

## 2. 安装与启动

### 2.1 普通用户（使用打包好的 exe）

1. 打开项目的 [Releases](https://github.com/liufeias/MergeTool/releases) 页面。
2. 下载最新版本的 `MergeTool-vX.Y.Z.zip`。
3. 解压到任意目录（**建议路径不含中文和空格**，例如 `D:\Tools\MergeTool`）。
4. 双击 `MergeTool.exe` 启动。

> ⚠️ 首次运行 Windows SmartScreen 可能提示"已保护你的电脑"，点击「更多信息」→「仍要运行」即可。
> 这是因为程序未做代码签名，并非病毒。

### 2.2 开发者（从源码运行）

需要 **Python 3.11 ~ 3.13** 与 **uv**（推荐）或 pip。

```powershell
git clone https://github.com/liufeias/MergeTool.git
cd MergeTool
uv sync
uv run python -m merge_tool
```

详细的环境搭建请见 [🛠 开发构建打包](BUILD.md)。

## 3. 界面总览

程序主界面分为三大区域：

```
┌─────────────────────────────────────────────────────────────────────┐
│  左侧设置面板（可滚动）            │   右侧主卡片（文件树）          │
│  ─────────────────────────────    │   ────────────────────────────  │
│  ① 数据源根目录 [输入框][浏览]     │   [已加载 N 项][已勾选 N 项]    │
│  ② 文件扩展名                      │            [🔍 搜索框]          │
│  ③ 包含无扩展名 / 递归子文件夹     │                                │
│  ④ 文件名筛选 + 使用正则           │   ┌─────────────────────────┐   │
│  ⑤ 文本读取编码 [下拉]             │   │  ☑ 📁 src               │   │
│  ⑥ 合并输出目标文件 [另存为]       │   │    ☑ 📄 app.py    41 KB │   │
│  ⑦ 平铺视图                        │   │    ☐ 📄 main.py    2 KB │   │
│  ⑧ [扫描目录] [应用筛选]           │   └─────────────────────────┘   │
│  ⑨ [开始合并文件]  （薄荷绿）      │                                │
│  ⑩ [取消当前任务]  （浅红）        │                                │
└─────────────────────────────────────────────────────────────────────┘
│  底部状态栏：进度条 + 状态文本                                        │
└─────────────────────────────────────────────────────────────────────┘
```

### 各区域功能

| 编号 | 控件 | 功能 |
| --- | --- | --- |
| ① | 数据源根目录 | 指定扫描起点。也可直接把文件/文件夹拖进窗口。 |
| ② | 文件扩展名 | 逗号分隔，如 `py,txt,md,json`。留空表示不限。 |
| ③ | 复选框 | 「包含无扩展名」决定是否纳入无后缀文件；「递归子文件夹」决定是否深入子目录。 |
| ④ | 文件名筛选 | 按文件名过滤。勾选「使用正则表达式匹配」后按正则处理。 |
| ⑤ | 文本读取编码 | 默认「自动检测」，也可强制指定编码。 |
| ⑥ | 合并输出目标文件 | 合并结果写到哪里，默认 `merged_content.txt`。 |
| ⑦ | 平铺视图 | 勾选后所有文件扁平展示，不显示目录层级。 |
| ⑧ | 扫描目录 / 应用筛选 | 扫描目录重新加载；应用筛选按当前条件重新扫描。 |
| ⑨ | 开始合并文件 | 把已勾选文件写入目标文件。 |
| ⑩ | 取消当前任务 | 中断正在运行的扫描或合并。 |

### 右侧文件树

- **复选框**：单击切换勾选状态。
- **目录**：勾选目录会级联勾选/取消其下全部文件，目录本身呈现三态（☑ 全选 / ◪ 半选 / ☐ 未选）。
- **展开/折叠**：点击左侧三角，或**双击文件夹整行**。
- **右键菜单**：全选、反选、全不选、展开全部、折叠全部、移除选中项、清空列表。
- **搜索框**：实时按文件名过滤（180ms 防抖）。
- **快捷键**：`Delete` 移除选中项，`空格` 切换选中项勾选状态。

## 4. 完整操作流程

### 步骤 1：选择数据源

- 方式 A：点击「浏览」，选择根文件夹。
- 方式 B：**直接把文件夹或文件拖进窗口任意位置**。
  - 拖入文件夹：自动填入根目录并开始扫描。
  - 拖入文件：自动作为独立条目追加到当前列表（自动去重）。
  - 同时拖入多个：文件夹作为根目录，其余文件追加进去。

### 步骤 2：配置筛选条件

例如只想合并项目里的 Python 和 Markdown 文件：

1. 文件扩展名填 `py,md`。
2. 勾选「递归子文件夹」。
3. 不勾选「包含无扩展名」。
4. 文件名筛选留空（不额外过滤）。

如果想排除测试文件：

1. 文件名筛选填 `^test_`。
2. 勾选「使用正则表达式匹配」。

### 步骤 3：扫描目录

点击「扫描目录」，等待右侧文件树加载完成。
状态栏会实时显示「已检索 N 个文件…」。

### 步骤 4：勾选要合并的文件

- 点击文件左侧复选框逐个勾选。
- 点击目录复选框级联勾选整个目录。
- 右键菜单可「全选所有文件 / 反选 / 全不选」。
- 顶部徽章实时显示「已加载 N 项 / 已勾选 N 项」。

### 步骤 5：确认输出路径

默认输出到程序当前目录的 `merged_content.txt`。
点击「另存为」可指定其他位置与文件名。

### 步骤 6：开始合并

点击「开始合并文件」。若目标文件已存在，会弹出覆盖确认。
合并过程中进度条与状态文本实时更新。

完成后弹出结果对话框，显示成功文件数、失败文件数与输出路径。

## 5. 筛选规则详解

### 5.1 文件扩展名

| 输入 | 含义 |
| --- | --- |
| `py,txt,md` | 只要这三种扩展名 |
| `.py, .TXT` | 前导点和大小写都可忽略，等价 `py,txt` |
| 留空 | 不限制扩展名（但仍受「包含无扩展名」影响） |

### 5.2 包含无扩展名

- 勾选：`Makefile`、`LICENSE`、`Dockerfile` 等无后缀文件也会被纳入。
- 不勾选：跳过这些文件。

### 5.3 递归子文件夹

- 勾选：深入所有子目录。
- 不勾选：只扫描根目录一层。

### 5.4 文件名筛选

- 不勾选正则：按**子串匹配**（大小写不敏感）。
- 勾选正则：按**Python 正则表达式**匹配，作用于文件名（不含路径）。

正则示例：

| 目的 | 正则 |
| --- | --- |
| 以 `test_` 开头 | `^test_` |
| 以 `.bak` 结尾 | `\.bak$` |
| 包含 `config` 或 `settings` | `config\|settings` |
| 纯数字文件名 | `^\d+$` |

> ⚠️ 合并阶段的「文件名筛选」是**二次校验**：扫描时已按扩展名过滤，合并时会再按文件名筛选规则复查一遍，确保只写入符合最终条件的文件。

## 6. 勾选与选择技巧

- **半选状态**：目录下部分文件被勾选时显示 ◪。
- **级联规则**：
  - 勾选目录 → 其下所有子目录与文件全部勾选。
  - 取消目录 → 其下所有子目录与文件全部取消。
  - 取消某个子文件 → 其所有祖先目录自动变为半选或未选。
- **选中行 + 空格**：批量切换勾选状态。
- **右键 → 全选选中条目**：只对当前高亮的行生效。

## 7. 编码检测说明

MergeTool 采用多级级联的编码检测策略：

1. **BOM 头**：最可靠，覆盖 UTF-8-SIG / UTF-16 / UTF-32。
2. **chardet 采样**：读取前 256 KB，要求置信度 > 0.7，并用更长样本做严格解码二次校验。
3. **UTF-8 严格解码试探**：能通过即为 UTF-8。
4. **GB18030 严格解码试探**：中文老项目覆盖最广。
5. **latin-1 兜底**：1 字节 1 字符，永不失败。

### 手动指定编码

左侧「文本读取编码」下拉可选：

- 自动检测（默认，推荐）
- UTF-8 / UTF-8-SIG（带 BOM）
- GB18030（推荐中文）/ GBK / GB2312
- BIG5
- UTF-16 LE / UTF-16 BE / UTF-32
- Latin-1 / ASCII

> 何时需要手动指定？当你**明确知道**所有文件都是某种编码，且自动检测出现误判时。
> 例如整批文件都是无 BOM 的 GBK，可强制选择「GBK」或「GB18030」。

## 8. 输出文件格式

输出文件使用 **UTF-8-SIG** 编码（Windows 记事本打开不乱码），换行为 `\n`。

结构如下：

```
======================================================================
文件内容合并工具 - 输出报告
======================================================================
生成时间: 2026-10-10 16:19:17
根目录: E:\MyPythonProgram\MergeTool
文件总数: 13
编码模式: 自动检测
扩展名筛选: （不限）
包含无扩展名文件: 否
递归搜索: 是
文件名筛选: （无）
使用正则: 否

--- 文件内容格式说明 ---
每个文件的数据块遵循以下格式:
1. 以 '文件绝对路径: ' 开头，后跟文件的完整路径。
2. 从下一行开始，是该文件的完整、原始内容。
3. 每个文件的数据块之后会有一个空行，用于与下一个文件分隔。

======================================================================
======================= 合并内容开始 =======================
======================================================================

文件绝对路径:  E:\MyPythonProgram\MergeTool\pyproject.toml
文件编码: utf-8 | 大小: 3.85 KB
----------------------------------------------------------------------
<文件原始内容>

文件绝对路径:  E:\MyPythonProgram\MergeTool\README.md
文件编码: utf-8 | 大小: 133.00 B
----------------------------------------------------------------------
<文件原始内容>

...

======================================================================
======================= 合并内容结束 =======================
======================================================================

成功合并文件数: 13
```

每个文件块包含三行头部：

1. `文件绝对路径:  <绝对路径>`
2. `文件编码: <实际使用编码> | 大小: <人类可读大小>`
3. `----------------------------------------------------------------------`

随后是文件原始内容，最后补一个空行作为分隔。

## 9. 常见问题 FAQ

### Q1：拖入文件没反应？

- 确认拖入的是**本地文件/文件夹**，而不是网页链接或压缩包内的文件。
- 某些以管理员权限运行的程序（如 7-Zip 管理员模式）拖拽会被 Windows UIPI 拦截。
- 尝试改用「浏览」按钮。

### Q2：合并后中文乱码？

- 先确认源文件真实编码，再在左侧「文本读取编码」手动指定。
- 若整批是 GBK，选「GB18030（推荐中文）」最稳。
- 输出文件本身是 UTF-8-SIG，用 VSCode / Notepad++ 打开一般不会乱码。

### Q3：输出文件太大怎么办？

- 用扩展名与文件名筛选缩小范围。
- 分批合并（例如按子目录分别输出）。
- 避免合并二进制文件（本工具面向文本，二进制会被 latin-1 兜底读成乱码）。

### Q4：勾选了目录，为什么有些文件没被合并？

检查以下可能：

1. 扩展名筛选排除了它们。
2. 「包含无扩展名」未勾选，无后缀文件被跳过。
3. 文件名筛选（或正则）不匹配。
4. 这些文件在扫描后被手动移除了。

### Q5：程序卡死 / 无响应？

- 扫描超大目录（数十万文件）时需要时间，但 UI 不会真正卡死，状态栏会持续更新。
- 若确实卡住，点击「取消当前任务」。
- 仍无响应时可强制结束进程，并考虑缩小根目录范围。

### Q6：能否合并二进制文件？

不建议。MergeTool 面向**文本文件**，二进制内容会被强行解码为乱码写入。
如需归档二进制，请使用 zip / 7z 等工具。

### Q7：输出路径支持中文吗？

支持。但**程序自身所在目录**建议不含中文和空格，避免极少数环境下的路径解析问题。

### Q8：为什么打包后的 exe 这么大？

PySide6 本身较大。本项目已通过 `MergeTool.spec` 中的 `excludes` 排除了
QtWebEngine、Qt3D、QtCharts、QtQuick 等无用模块，产物约 80–150 MB。
详见 [🛠 开发构建打包](BUILD.md)。
